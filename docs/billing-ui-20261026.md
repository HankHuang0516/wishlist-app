# 贊助與升級介面更新

使用者於2026-10-26明確要求依照已提出的AI示意圖優化內購UI、讓購買入口更直接，完成驗收後發布更新；並確認已內測過付款流程。示意圖`Wishlist/Design/billing-ui-20261026/billing-ui-proposal-v1.png`作為本次視覺與資訊架構目標。示意價格和餘額不屬實際帳號資料；實作以當地商店displayPrice與伺服器權益為準。

「我的」提供單一「查看方案與購買」入口。總覽依序呈現免費額度、尊榮訂閱、行銷永久加值、純贊助，每個方案有明確可點按鈕；詳情呈現權益、付款週期、續訂方式、取消與政策連結，最後固定底部的CTA才向原平台請求購買。

取消會明確顯示。商店回覆前顯示等待狀態；35秒沒有回覆不當作失敗，也不自動重試付款，須先查核原交易。收據在伺服器驗證後才顯示成功；Google消耗／確認仍在持久帳本後由後端完成。恢復購買不產生新購買，依序核對所有回傳的本App商品；零筆與失敗有明確說明。Apple新購買仍依平台開關關閉，既有交易恢復保留。

原生候選為Android2.0.18(40)、iOS2.0.18(22)。Android依現有正式與internal軌道更新；iOS21的既有退件（手機必填、訪客瀏覽、UGC實機影片）不能因UI改版視為解決，22不擅自沿用21專屬影片授權送審。

驗收證據存於`Wishlist/QA/billing-ui-20261026/`。功能與UIUX各須至少85，分平台記錄工程審查，不聲稱像素相似度或商店核准。原生畫面用實際NativeBilling/BillingViews搭配明示的合成SDK與帳號驗證，不宣稱代理完成真實付款。正式包另核對來源、簽章、權限與本版圖示；保留20GiB SSD餘量，雲端EAS建置正式包。
